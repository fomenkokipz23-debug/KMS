## Закріплення теми

### 1. Закон Амдала

**Вихідні дані:**

- Частка послідовного коду: \(f = 25\% = 0{,}25\).
- Частка паралельного коду: \(1-f = 75\% = 0{,}75\).

Для розрахунку прискорення використовуємо закон Амдала:

\[
S = \frac{1}{f + \frac{1-f}{p}}
\]

де:
- \(S\) - прискорення виконання програми;
- \(f\) - частка послідовного коду;
- \(p\) - кількість процесорних ядер.

**Для 4 ядер:**

\[
S = \frac{1}{0{,}25 + \frac{0{,}75}{4}}
\]

\[
S = \frac{1}{0{,}25 + 0{,}1875}
= \frac{1}{0{,}4375} \approx 2{,}29
\]

**Для 8 ядер:**

\[
S = \frac{1}{0{,}25 + \frac{0{,}75}{8}}
\]

\[
S = \frac{1}{0{,}25 + 0{,}09375}
= \frac{1}{0{,}34375} \approx 2{,}91
\]

**Для 16 ядер:**

\[
S = \frac{1}{0{,}25 + \frac{0{,}75}{16}}
\]

\[
S = \frac{1}{0{,}25 + 0{,}046875}
= \frac{1}{0{,}296875} \approx 3{,}37
\]

**Висновок:**

Зі збільшенням кількості ядер прискорення програми зростає, але приріст поступово зменшується. Теоретична межа прискорення за законом Амдала становить:

\[
S_{max} = \frac{1}{f} = \frac{1}{0{,}25} = 4
\]

Отже, навіть за великої кількості ядер програма не може прискоритися більше ніж у 4 рази за заданої частки послідовного коду. Це демонструє ефект спадної віддачі від збільшення кількості ядер.

### 2. Визначення типу конфлікту конвеєра (Hazard)

**Псевдокод:**

```assembly
ADD R1, R2, R3   ; R1 = R2 + R3
SUB R4, R1, R5   ; R4 = R1 - R5
```

**Тип конфлікту:** конфлікт за даними (Data Hazard).

**Пояснення:**

Перша команда `ADD` обчислює суму значень регістрів `R2` і `R3` та записує результат у `R1`.

Наступна команда `SUB` використовує значення `R1` для обчислення різниці. Виникає залежність між командами, оскільки друга команда потребує результату першої.

Якщо результат ще не готовий, конвеєр може затримати виконання команди `SUB` за допомогою зупинки (`stall`) або вставки тактів очікування (`bubble`). За наявності механізму пересилання даних (`forwarding`) затримку можна зменшити або усунути.

### 3. Приклад коду з умовним переходом

**Приклад коду на C:**

```c
if (x > 0) {
    y = a + b;
} else {
    y = a - b;
}
```

**Тип конфлікту:** конфлікт за керуванням (Control Hazard).

**Пояснення:**

Умовний оператор визначає, яку гілку програми потрібно виконати залежно від значення `x`.

У конвеєрному процесорі наступні інструкції можуть почати завантажуватися ще до того, як результат перевірки умови стане відомим. Якщо процесор неправильно передбачив напрямок переходу, він повинен скасувати інструкції, які вже почав виконувати, і завантажити правильні.

Це може призвести до втрати тактів і зниження продуктивності. Для зменшення таких затримок використовують передбачення переходів (Branch Prediction).

## Підготовка до наступного заняття (Лекція №13)

### Запитання

Чому дані під час передавання мережею розбивають на рівні за моделлю OSI, а не передають одним суцільним потоком?

**Відповідь:**

Поділ мережевої взаємодії на рівні забезпечує модульність, стандартизацію та гнучкість. Кожен рівень виконує окремі завдання й взаємодіє із сусідніми рівнями через визначені інтерфейси.

Це дозволяє змінювати технології передавання даних без необхідності повністю змінювати програмне забезпечення. Наприклад, застосунок може працювати через Wi-Fi або Ethernet без зміни своєї основної логіки.

Рівнева модель також спрощує розробку мережевих протоколів, маршрутизацію, контроль помилок і пошук несправностей.

## Контрольні запитання та відповіді (Лекція №12)

1. **Що таке конвеєрне виконання і яке теоретичне прискорення воно дає?**  
   Конвеєрне виконання (pipelining) - це техніка організації процесора, при якій виконання команди розбивається на кілька послідовних стадій (вибірка, декодування, виконання, доступ до пам'яті, запис результату), і поки одна команда перебуває на пізній стадії, наступна вже проходить ранню. За ідеальних умов конвеєр із $N$ стадіями теоретично здатний наблизитися до $N$-кратного прискорення виконання програми.

2. **Наведіть приклади структурного конфлікту, конфлікту за даними і за керуванням.**  
   * **Структурний конфлікт:** дві команди одночасно потребують одного й того самого апаратного ресурсу (наприклад, одночасний доступ двох стадій до одного блоку пам'яті).  
   * **Конфлікт за даними (data hazard):** команда додавання обчислює значення регістру, яке наступна команда віднімання намагається прочитати ще до того, як результат буде записано у регістровий файл.  
   * **Конфлікт за керуванням (control hazard):** виконання умовного переходу (розгалуження за результатом порівняння), коли адреса наступної інструкції невідома до етапу обчислення умови.

3. **Чим суперскалярне виконання відрізняється від простого конвеєра?**  
   Класичний конвеєр спроможний передавати на кожну стадію лише одну команду за такт. Суперскалярне виконання дозволяє вибирати, декодувати та виконувати декілька незалежних команд одночасно в межах одного такту завдяки наявності кількох паралельних виконавчих пристроїв (наприклад, двох АЛП).

4. **Що станеться, якщо передбачення переходу виявиться помилковим при спекулятивному виконанні?**  
   Якщо передбачення виявилося хибним, результати спекулятивно виконаних команд скасовуються, конвеєр повністю очищається (flush), а процесор починає вибірку інструкцій з правильної гілки розгалуження, що призводить до втрати декількох тактів.

5. **Сформулюйте суть закону Амдала і його практичний наслідок для багатопоточних програм.**  
   Закон Амдала визначає теоретичну межу прискорення програми при розпаралелюванні: загальне прискорення обмежене часткою коду, яку взагалі можливо виконати паралельно, оскільки послідовна частина виконується незалежно від кількості ядер. Практичний наслідок полягає в тому, що нарощування кількості процесорних ядер має межу ефективності (ефект спадної віддачі), і якщо послідовна частка коду значна, додаткові ядра не дадуть відчутного приросту швидкості.

6. **Що таке big.LITTLE і навіщо потрібні гетерогенні ядра?**  
   big.LITTLE — це архітектурний підхід, за якого на одному кристалі поєднуються високопродуктивні енергоємні ядра («big») та економічні менш продуктивні ядра («LITTLE»). Гетерогенні ядра потрібні для оптимізації енергоефективності: фонові й невимогливі задачі виконуються на «LITTLE»-ядрах для збереження заряду батареї, а ресурсомісткі застосунки переносяться ОС на «big»-ядра.

7. **Чому пересилання даних (forwarding) дозволяє уникнути зупинки конвеєра при конфлікті за даними, а в яких випадках зупинка (stall) все одно неминуча?**  
   Пересилання даних передає обчислений результат напряму між стадіями (наприклад, зі стадії виконання $E$ на вхід $E$ наступної команди), оминаючи тривале очікування запису в регістровий файл. Проте зупинка неминуча, якщо результат стає відомим лише на стадії доступу до пам'яті $M$ (наприклад, при команді завантаження з пам'яті `lw`), а наступній інструкції ці дані потрібні вже на стадії $E$.

8. **Чому теоретичне 4-кратне прискорення від SIMD-інструкції для 4 елементів даних рідко досягається на практиці повністю?**  
   Реальний виграш залежить від того, чи вирівняні дані в пам'яті, від накладних витрат на завантаження/упаковку векторних регістрів, а також від здатності компілятора автоматично векторизувати цикли без виникнення залежностей за даними.

9. **За формулою закону Амдала: до якого максимального прискорення можна наблизитись, якщо послідовна частка коду f = 0,2, незалежно від кількості ядер?**  
   Максимальне прискорення виражається граничним значенням $S_{max} = \frac{1}{f}$. При $f = 0,2$ максимальне теоретичне прискорення дорівнює $\frac{1}{0,2} = 5$ разів (навіть при нескінченній кількості ядер $p \to \infty$).
