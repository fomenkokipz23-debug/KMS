# Самостійна робота №10: Стандарти мереж: IEEE 802 і структура RFC Варіант №4

**Тема:** Стандарти мереж: 'IEEE 802' і структура 'RFC'  
**Протокол:** SMTP (Simple Mail Transfer Protocol)  
**URL першоджерела:** [https://datatracker.ietf.org/doc/html/rfc5321](https://datatracker.ietf.org/doc/html/rfc5321)

---

## 1. Основний RFC протоколу SMTP

| Поле | Значення |
| :--- | :--- |
| **Номер RFC** | RFC 5321 |
| **Повна назва** | Simple Mail Transfer Protocol |
| **Рік публікації** | Жовтень 2008 року |
| **Статус** | Draft Standard (входить до стандарту інтернет-протоколів) |
| **Автор / Організація** | J. Klensin / Network Working Group (IETF) |

---

## 2. Перевірка чинності документа
Документ **RFC 5321 є чинним (Active)**.  
* **Obsoletes:** RFC 2821, RFC 821 (замінив їх).
* **Obsoleted by:** Відсутній (жоден новий документ не замінив RFC 5321).
* **Updated by:** RFC 7504, RFC 9084.

 RFC 5321 є основним та актуальним стандартом протоколу SMTP на сьогодні.

---

## 3. Конкретні факти з тексту RFC 5321

1. **Номер порту за замовчуванням (Розділ 2.3.5):**  
   Згідно з розділом 2.3.5, сервер SMTP за замовчуванням слухає порт **25** (TCP port 25) для передачі пошти між агентами пересилання (MTA).

2. **Обмеження на довжину команд та рядків (Розділ 4.5.3.1):**  
   Специфікація встановлює жорсткі обмеження на розміри елементів:
   - Максимальна довжина команди (command line) становить **512 октетів** (включаючи символи CRLF).
   - Максимальна довжина імені користувача в поштовій скриньці (local-part) становить **64 октети**.
   - Максимальна довжина доменного імені становить **255 октетів**.

## 4. Підгрупи родини IEEE 802

| Підгрупа | Область відповідальності |
| :--- | :--- |
| **IEEE 802.1** | Архітектура мереж, керування мережами, мости (bridging) та безпека в LAN/MAN. |
| **IEEE 802.3** | Стандартизація проводових локальних мереж Ethernet (фізичний та MAC-рівні). |
| **IEEE 802.11** | Стандартизація безпроводових локальних мереж Wi-Fi (WLAN). |

##  Контрольні запитання

1. **Чим статус «Proposed Standard» відрізняється від «Internet Standard»?**  
   *Відповідь:* **Proposed Standard** - це початковий етап стандартизації: специфікація вважається стабільною та корисною, але потребує подальшого тестування й перевірки на практиці. **Internet Standard** - це найвищий рівень зрілості документа, який гарантує високий рівень технічної досконалості та масштабне успішне впровадження протоколу в мережі Інтернет.

2. **Що означають поля «Obsoletes» і «Updated by» на сторінці RFC?**  
   *Відповідь:* Поле **Obsoletes** вказує номери застарілих документів, які даний RFC повністю замінює та анулює. Поле **Updated by** вказує на новіші RFC, які вносять окремі поправки, доповнення або розширення у цей документ, не скасовуючи його повністю.

3. **За що відповідає підгрупа IEEE 802.1 і чим вона відрізняється від 802.3?**  
   *Відповідь:* **IEEE 802.1** відповідає за загальну архітектуру локальних мереж, маршрутизацію/комбінування (VLAN, Spanning Tree) та безпеку на вищому рівні. На відміну від неї, **IEEE 802.3** вузько спеціалізується виключно на фізичному каналі та MAC-рівні проводового стандарту Ethernet (кабелі, швидкості, кадри).

4. **Чому недостаточно знайти будь-який RFC з назвою протоколу в заголовку, не перевіривши актуальність?**  
   *Відповідь:* Застарілі RFC (наприклад, RFC 821 для SMTP) можуть містити вразливості, застарілі параметри або скасовані механізми. Неперевірений RFC може призвести до використання неактуальних рішень у розробці та налаштуванні мереж.
