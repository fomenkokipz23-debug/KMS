##  Исходные данные

- **Адрес для сокращения и классификации:** 2001:0db8:0000:0042:0000:8a2e:0370:7334
- **Префикс для разделения на 16 подсетей:** fd00:1234:5678::/48

---

## 1. Сокращение IPv6-адреса

Исходный адрес:

2001:0db8:0000:0042:0000:8a2e:0370:7334

**Шаг 1.** Убираем ведущие нули в каждой 16-битной группе:

2001:db8:0:42:0:8a2e:370:7334

**Шаг 2.** Заменяем одну из групп нулей на ::. Поскольку обе группы содержат одинаковое количество нулей, можно сократить любую из них.

**Результат:**

2001:db8::42:0:8a2e:370:7334

---

## 2. Определение типа IPv6-адреса

Исходный адрес:

2001:0db8:0000:0042:0000:8a2e:0370:7334

- **Первый блок:** 2001
- **Диапазон:** 2000::/3
- **Тип:** Global Unicast Address (глобальный одноадресный адрес).

Адреса из диапазона 2000::/3 относятся к глобальным одноадресным адресам. Однако префикс 2001:db8::/32 зарезервирован для документации и примеров и не предназначен для обычной маршрутизации в Интернете.

---

## 3. Разделение префикса на 16 подсетей

**Исходный префикс:** fd00:1234:5678::/48

Для получения 16 подсетей необходимо добавить 4 бита, поскольку:

2^4 = 16

Новая длина префикса:

48 + 4 = 52

Следовательно, каждая подсеть будет иметь префикс /52.

### Первые три и последняя подсети

| Подсеть | Префикс |
|---|---|
| 0 | fd00:1234:5678:0000::/52 |
| 1 | fd00:1234:5678:1000::/52 |
| 2 | fd00:1234:5678:2000::/52 |
| 15 | fd00:1234:5678:f000::/52 |

Четыре дополнительных бита занимают старшую часть четвёртого блока IPv6-адреса. Их значения изменяются от 0 до f, что позволяет получить 16 подсетей.

## 4. Поиск собственного IPv6-адреса

Для просмотра IPv6-адресов сетевых интерфейсов можно использовать следующие команды.

**Linux:**

```bash
ip -6 addr
```

**Windows:**

```powershell
ipconfig
```

### Пример вывода

```text
inet6 fe80::1ff:fe23:4567/64 scope link
inet6 2001:db8:1234:5680:abcd:ef12:3456:7890/64 scope global dynamic mngtmpaddr
```

*Примечание: приведённые адреса являются примерами, а не результатами проверки реального устройства.*

### Анализ адресов

**1. Link-local:**

fe80::1ff:fe23:4567

- Используется для связи внутри локального канального сегмента сети.
- Адреса этого типа начинаются с префикса fe80::/10.
- Обычно назначаются автоматически.

**2. Global Unicast:**

2001:db8:1234:5680:abcd:ef12:3456:7890

- Глобальные одноадресные адреса предназначены для межсетевого взаимодействия.
- В обычной сети адрес может назначаться с помощью SLAAC или DHCPv6.
- Префикс 2001:db8::/32 используется для документации, поэтому данный пример не является обычным публичным адресом для Интернета.

## 6. Контрольные вопросы

### 1. Сколько раз в пределах одного IPv6-адреса можно использовать обозначение :: и почему?

**Ответ:** Обозначение :: можно использовать только один раз. Оно заменяет одну или несколько последовательных групп нулей. Если использовать его несколько раз, запись станет неоднозначной, поскольку нельзя будет точно определить количество пропущенных групп.

### 2. По каким битам адреса можно определить Link-local и Multicast?

**Ответ:**

- **Link-local:** префикс fe80::/10, первые 10 бит - 1111111010.
- **Multicast:** префикс ff00::/8, первые 8 бит - 11111111.

### 3. Чем Unique Local Address (ULA) отличается от Global Unicast по назначению?

**Ответ:** ULA используется преимущественно для внутренней адресации и маршрутизации внутри локальных сетей и организаций. Такие адреса входят в диапазон fc00::/7, обычно используется префикс fd00::/8. Они не предназначены для маршрутизации в глобальном Интернете.

Global Unicast используется для глобальной межсетевой связи и может маршрутизироваться в Интернете при условии корректного назначения адреса и настройки сети.

### 4. Что изменилось в заголовке IPv6 по сравнению с IPv4 и почему убрали контрольную сумму заголовка?

**Ответ:** Основной заголовок IPv6 имеет фиксированный размер 40 байт. В нём отсутствуют некоторые поля IPv4, например контрольная сумма заголовка и поля фрагментации в основном заголовке. Для дополнительных функций используются расширенные заголовки.

Контрольную сумму заголовка убрали, чтобы уменьшить затраты времени на обработку пакетов маршрутизаторами. Это стало возможным благодаря проверке целостности данных на других уровнях сетевого взаимодействия.
